# v2 Development

This is the **2.0.6 manual-test candidate**, not an approved store release. Both contributors use develop; main remains the confirmed 1.22.6 release. V1 fixes can branch from main and be brought into develop afterward.

The reported empty Packages preview was traced to Chrome omitting tab/document sender fields on direct extension-tab-to-content messages. The worker now binds the original source document before opening export and authenticates the one-use claim to the created export document. Only preview, verify, read, and cancel operations are relayed to that original top-level source document. The isolated receiver rejects the old direct route; caller fields cannot replace the source target, client identity, or advanced consent. Source reload or a cleared browser/extension session still fails safely rather than retargeting a new document; normal worker sleep now restores its exact claimed document grants from memory-only storage.session. Native tenant/manager checks, consent, exact eligibility, request limits, and explicit downloads remain unchanged. Installed-extension synthetic end-to-end checks now pass; signed-in testing remains required. Settings regrouping remains on hold for discussion.

## Implemented

- Settings grouped by where they apply, preserving existing preference keys, favorites, cache format, and backups.
- A dismissible What's New card on the next settings opening after an update. No automatic tabs or source collection.
- Both export modes launch from **Integration Packages**, in a dedicated extension tab independent of the settings popup. Designer only populates Shared From observations.
- Default eligibility requires Shared From consent and exact Designer-recorded package/pipeline relationships. Unassigned package names cannot authorize downloads; forgiving search normalization does not expand matches. Saved observations may be stale and are not service permissions.
- Fresh latest package references and eligible package definitions populate preview, including API/Sub-Pipeline metadata omitted from native runnable lists. Preview requests no pipeline source code. Every package heading is listed immediately. Native collapsible groups lazily render all eligible pipeline rows when opened, with package/pipeline checkboxes, Select All, mixed states, and selected counts. Only checked records are downloaded; there is no exporter Show More cap.
- **Download ZIP** explicitly retrieves the newest published Pipeline, API, or Sub-Pipeline per name/type. **Save ZIP** downloads the locally assembled archive, with each package folder containing its JSON files.
- Shift+D while settings is open and not typing reveals a temporary advanced option. A separate warning confirms Include All Accessible Content. This bypasses only the saved-source filter, not authentication or service access. Unclaimed launch tickets remain short-lived and RAM-only. Claimed document grants retain temporary consent in browser-memory session storage through normal worker sleep, never as a permanent preference. Callers may narrow or revoke it but cannot elevate it; cancel/close clears it.
- The v1.22.7 Packages favorites tenant-context fix and v1.22.8 existing-draft published-fitting viewing fix, without resetting saved pins or changing storage formats.
- Progress, Cancel, Refresh Preview, fixed failure messages, response projection, and original source document/manager/site/tenant checks. Lost consent, removed membership, navigation, failure, or cancellation discards partial output.

## Native Readers and Limits

Packages' existing native helpers own authentication. The extension passes the existing session callback to them; it does not invoke it itself or inspect token/header values. Their opaque authentication configuration stays in the MAIN world, passed directly between native helpers without inspection, copying, logging, storage, or extension messages.

The native reference-list reader is explicitly called without its default all-package fan-out. Package and source reads use a combined six-job budget with sharing lookups. A cancelled or timed-out call occupies capacity until the actual native promise settles; retry cannot launch six more over stalled calls. The extension cannot stop native services that lack abort support.

Pipeline/API reads use exact full-version paths. Sub-Pipeline reads use the package-reported major version, which resolves to its current source without requiring parent-pipeline republishing for compatible updates. Their preview retains the package-reported full version; it is not proof of the downloaded source's exact minor/patch. Null/omitted source versions are accepted without rewriting JSON. A supplied version must be valid and match the requested major; another major, wrong source name/type, or a Pipeline/API version mismatch fails. Native helpers return parsed JSON, so output preserves content but may use different whitespace. Source filenames use safe Windows-compatible escaping and collision checks. ZIP entries use standard uncompressed storage; limits are 10,000 files and 64 MB of source JSON. An empty or inaccessible response is a failure, not a successful empty export.
