## Native Readers and Limits

Packages' existing native helpers own authentication. The extension passes the existing session callback to them; it does not invoke it itself or inspect token/header values. Their opaque authentication configuration stays in the MAIN world, passed directly between native helpers or to the approved native HTTP client without inspection, copying, logging, storage, or extension messages.

The native reference-list reader is explicitly called without its default all-package fan-out. Package and source reads use a combined six-job budget with sharing lookups. A cancelled or timed-out call occupies capacity until the actual native promise settles; retry cannot launch six more over stalled calls. The extension cannot stop native services that lack abort support.

Pipeline/API reads use exact full-version paths. Sub-Pipeline reads use the package-reported major version, which resolves to its current source without requiring parent-pipeline republishing for compatible updates. Their preview retains the package-reported full version; it is not proof of the downloaded source's exact minor/patch. Null/omitted source versions are accepted without rewriting JSON. A supplied version must be valid and match the requested major; another major, wrong source name/type, or a Pipeline/API version mismatch fails. Native helpers return parsed JSON, so output preserves content but may use different whitespace. Transformers use the fixed latest endpoint described above and preserve its JavaScript text unchanged. Source filenames use safe Windows-compatible escaping and collision checks. ZIP entries use standard uncompressed storage; limits are 10,000 files and 64 MB of source content. An empty or inaccessible response is a failure, not a successful empty export.
