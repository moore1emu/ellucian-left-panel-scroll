GitHub Token Settings

Open GitHub's fine-grained token page:

  • Token name: e.g. Integration Navigator Test
  • Expiration: e.g. 7 days for testing; renew before it expires
  • Resource owner: Repository owner
  • Repository access: Only select repositories → choose your repository
  • Contents: Read and write
  • Other permissions: Leave unchanged; Metadata read is automatic

Organization approval may be required. Generate the token and paste it into the field above.

GitLab Token Instructions

Follow GitLab's project token guide. In your project, open Settings → Access tokens → Add new token:

  • Token name: e.g. Integration Navigator Test
  • Expiration: Choose a date, e.g. 7 days from today for testing
  • Role: Developer for an unprotected export branch
  • Scope: api, not write_repository alone
  • Finish: Create the token and paste it into the field above

Creating project tokens requires Maintainer/Owner access. GitLab.com requires Premium/Ultimate; organization policies apply.

Automatic reuse after restart. This is not an OS vault and does not protect a compromised browser profile.

Unlock once per browser session or lock manually. No idle-lock timer. A lost password cannot be recovered; reconnect with a new token.
