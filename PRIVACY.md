# Privacy Policy

This policy describes the separate v3.0.9 test candidate. Its optional Git workflow adds the consented uploads and credential storage below. The earlier offline design mockup remains a simulation, not the functional connection page. V2's release/policy and the live store listing are unchanged by this branch.

## Optional Git Connections and Uploads

The configured export folder is a base. Git export appends the saved Designer environment name for the exact verified current tenant ID and shows the resolved folder before confirmation. Missing/unsupported names or duplicate names among known cached tenants stop preparation; labels are not guessed from URLs or fetched from other environments. Names changing after preview require a new comparison. Tenant names therefore appear in confirmed Git paths and local successful receipts; no additional lookup, persistent mapping, token disclosure, or automatic folder migration/deletion is added. Existing saved base values remain until explicitly resaved with a fresh token. Browser sign-in to view private commit links is separate from API authentication.

Git is unused until you configure a destination in the extension-owned Git Connection tab. You enter a provider access token, existing repository/branch, dedicated folder, storage choice, and upload consent. Self-hosted GitLab accepts HTTPS DNS origins without URL prefixes or custom ports. Allow Server Access requests only that exact API origin. Up to 20 non-secret reserved Git origins are saved locally so Git permissions cannot enroll a server as an Experience site or inject page scripts. Forget retains those reservations/browser grants; revoke site access in browser extension details if needed. Reservations themselves grant no access.

Tokens are encrypted using AES-256-GCM with random IVs and destination/revision-bound authentication data in extension-origin IndexedDB. Device mode stores a non-extractable key there for automatic reuse; this is not an OS vault or protection against compromised trusted extension code or an accessible browser profile. Password mode uses PBKDF2-SHA-256, 600,000 iterations and a random salt; no password is saved. The unlocked key stays only in trusted-context Chrome storage.session until browser/extension restart or manual Lock, with no idle timer. Session-only mode similarly keeps its encryption key in memory; an unusable encrypted token record can remain after restart and must be replaced. Lost passwords cannot be recovered. No plaintext token/password enters local/sync storage, JSON backups, history, source grants, content/MAIN scripts, or logs. Browser/profile backups and compromised trusted contexts remain outside these protections.

Test Connection reads repository metadata only. Preview Git Changes explicitly retrieves selected sources through the same native authentication, ownership/override, document, tenant, version, and six-request safeguards as ZIP export, retaining generated files in export-tab memory. It reads repository visibility, branch/commit/tree identities, and changed GitLab files' HEAD identity metadata. Preview uploads no source payload. Your configured provider receives these metadata requests and may record access/audit logs. Git tokens go only in that API's authorization headers; cookies are omitted and redirects rejected. Ellucian session credentials are never reused for Git.

Only a second explicit confirmation and Push to Git sends the listed files. Add/update-only commits preserve unrelated files and never delete unselected/missing artifacts. Files, names, paths, and generated READMEs may contain confidential embedded values; review source and repository visibility first. Public repositories expose files, internal repositories may expose them organization-wide, and commits may trigger CI/CD. Saved-token encryption does not encrypt repository contents or remove old commits/provider retention. GitHub uploads objects before advancing the branch; later failure may leave unreferenced uploaded objects. GitLab uses a multi-action commit. Changed comparisons require a fresh preview; GitLab file-level guards are not an atomic whole-branch lease. Uncertain writes are checked when possible, never automatically replayed. Cancel/close/lock/forget/revocation cannot recall requests already sent or erase remote data.

Optional local history retains up to 20 successful receipts: provider/repository/branch/folder, commit ID, time, and changed-file count. It contains no credentials, headers, source payloads, or raw service errors and is excluded from JSON backup. Clear Local History clears only this list. Forget removes the saved active credential record, not its provider token, Git history, grants, reservations, or historical browser backups. Revoke the token at its provider if needed. No scheduled/automatic push, repository creation, force-push, remote restore, analytics, or publisher upload service is added. ZIP/JSON downloads remain independent and local.

The settings popup uses task tabs without saving your selected tab. It reads the active top-level Integration page's existing route/status to show context and disable unavailable source-refresh/export actions. This does not request pipeline contents, contact additional services, inspect unrelated tabs, add tab-URL permissions, or change saved preferences or consent. Backup/restore remains independent of the active page.

## What the extension does

This independent browser extension improves navigation in Ellucian Integration Packages and Integration Designer on the standard Ellucian Experience Test and Production websites and university vanity domains you explicitly add. It adds scrolling, resizing, search, favorites, and optional Shared To and Shared From columns. A separate **Show APIs & Sub-Pipelines** setting enables a Type column and read-only published records in Integration Packages, independently of Shared From.

For these read-only records, a page-start observer extracts only names, types, and published versions from the package metadata response requested by the page, before Ellucian filters its sidebar data. It keeps the newest Sub-Pipeline release within each major and the latest overall API release. It does not make or change requests, access headers or credentials, or retain response bodies. A bounded in-memory startup buffer is discarded as soon as the saved display opt-out is read; when off, subsequent response collection and record display stop. These records are not saved to browser storage or included in Designer-source exports. Disabling **Show APIs & Sub-Pipelines** or reloading/closing the page discards this transient data. New installs default to off; an upgrade preserves the previous display choice once, then stores the independent boolean preference. Turning Shared From off clears only its source cache and does not disable these reference records.

## Information used

The extension reads package and pipeline names, versions, and relevant page structure from the Ellucian page you are using. Search terms are processed in your browser. It uses the current site, tenant, and page context to keep navigation and optional sharing lookups within your existing Ellucian session.

When you enable Shared To, the extension uses Ellucian's existing authenticated page helpers to request pipeline sharing metadata and destination environment details from Ellucian. Those requests include the identifiers and pipeline names or versions needed by Ellucian's services. Results are cached in memory to limit repeated requests and can be refreshed manually. This feature is off by default.

The extension does not read, copy, or store your Ellucian password or bearer token. Git uses only the separately entered provider token described above. It does not request student records or pipeline execution data.

Shared From is a separate, optional feature that is off by default. It requires accepting a local-data notice before collection begins. On Designer pages you visit, it reads already-loaded package/pipeline names and separately records published transformer names, using the existing authenticated page helper to resolve that current environment's label. Grouping those names by package requires no additional service requests. It does not contact every environment from one page or fetch source contents. Integration Packages matches names against these locally observed Designer sources. This is an ownership inference, not a live record of sharing activity, and may be stale or unavailable.

## Local storage

The v2 development checkpoint also saves small version markers to show and dismiss What's New on the next settings opening after an update. These markers contain only extension version numbers and stay local. Opening or dismissing notes does not collect sources, reset preferences, or open a browser tab.

Export ZIP filenames and package READMEs reuse the saved Shared From environment name for the exact current tenant ID, with verified-ID fallback when no matching valid name is cached. No name-service lookup is made for export; page-supplied names do not override saved names or authorize access. Optional Formatted output is off by default and is not saved as a preference. When checked, the local archive includes Source/Formatted copies and one README per selected package, listing the environment and selected artifact names, types, majors, and package-reported versions. These files are generated from data already collected for that export, without additional source/audit lookups or code execution, and count toward the same archive limits. Formatted copies are for review, not import or execution. Unchecked output retains the prior package/file layout with no README. Environment names and source contents are not added to persistent export grants. ZIP creation itself uploads nothing; a separately confirmed Git push uploads selected generated files as described above.

**Pipeline Export** explicitly opens a separate extension tab from Integration Packages. Its preview requests latest package references and eligible package definitions through the page's existing authenticated native helpers, retaining only names, types, versions, and current document/site/tenant context. Pipeline/Sub-Pipeline selection keeps the newest published version within each available major; APIs/transformers retain latest-overall selection. Only checked records are retrieved, and type counts are calculated locally from that selection. Preview does not request pipeline source code or refresh Shared From. Default eligibility requires Shared From consent and exact package/pipeline names in your existing saved Designer observations. Preview metadata stays in memory and is not written to extension storage.

In the v2 test candidate, selecting **Download ZIP** explicitly retrieves chosen published Pipeline, API, and Sub-Pipeline JSON through those same native services, plus selected transformer JavaScript through a fixed read-only service path using the page's existing HTTP client. Native helpers prepare the authentication configuration; it is passed untouched to that client in the page world. The extension does not inspect token/header values, invoke the session callback itself, or copy authentication configuration into messages, files, logs, or storage. Source text/JSON is temporarily held in memory and assembled locally into a package-folder ZIP; JavaScript is never executed. The same action automatically requests the browser download only after complete successful assembly. **Download Again** retries the prepared local archive without additional source requests; browser save prompts/preferences still apply. Source contents may include confidential embedded values; review exported files before sharing and store them securely. Cancellation/failure discards partial output; closing the export tab discards temporary state. Completed downloads remain wherever you save them and cannot be removed by cancelling export or changing selection. ZIP creation does not upload these files, and neither export mode changes published Ellucian artifacts. A separately confirmed Git push uploads selected generated files as described above. Synthetic tests use no institution data; a separately owner-approved single transformer read verified text availability without logging source or credentials. Integrated signed-in ZIP confirmation remains pending.

Shift+D in settings can reveal a temporary advanced export option while you are not typing. Including accessible content absent from Designer observations requires a separate warning confirmation, does not grant service/site access, and is never saved as a preference. Both modes use Integration Packages. A short-lived, one-use in-memory launch ticket binds the confirmed workflow to its original source tab and created extension tab; it contains no token or source code. An unclaimed ticket is lost if the worker restarts; after a successful claim, the temporary document grant described below survives normal worker sleep. The choice resets in settings after launching/closing; the launched workflow retains it only until cancelled or closed.

After the export tab claims its launch, a bounded set of at most 20 temporary document grants is held in Chrome's memory-only storage.session, accessible only to trusted extension contexts by default. Each record contains browser tab/document identifiers, the source page URL, an opaque client identifier, a cancellation generation, extension version, and the temporary advanced-mode authorization flag. It contains no pipeline names or contents, authentication configuration, tokens, credentials, or favorites. These records survive ordinary background-worker sleep so an open export does not expire merely while you review the preview. Closing the source/export tab removes its records; extension reload/update/disable and browser restart clear session storage. Source navigation/reload does not authorize a replacement document. No local/sync-storage fallback or keep-alive polling is used; unavailable session storage stops export safely.

Your settings, custom Experience site domains, icon background and letter colors, icon letters, favorite icon shape, color and match-icon preference, column widths, favorite package and pipeline names, favorite version identifiers, ordering, and favorites layout preferences are saved in the browser's local extension storage. They are not synchronized by the extension to other devices or sent to the publisher. Pasted custom URLs are reduced to their HTTPS domain; paths, query strings, and fragments are not saved. Temporary search indexes and sharing results remain in page memory.

If you enable Shared From, an additional bounded local cache saves package and pipeline names grouped by environment, the identifiers and labels of their observed Designer environments, and last-checked timestamps. It does not keep a duplicate flat list of the same pipelines. Previously saved names without package relationships are preserved in an explicitly unknown-package group, retaining their original last-checked times until that Designer environment is refreshed. No pipeline contents, credentials, or execution data are stored in this cache. It is shared between this extension's supported environments on the same browser so Integration Packages can identify sources learned from other Designer environments. Revisit Designer in each source environment to refresh its snapshot. The **Refresh** button under Shared From uses only the active tab's identifier to request collection from that currently open Designer environment; it does not scan other tabs or contact other environments. Export JSON is in Backup & Restore. Automatic startup waits briefly for loaded page data with a bounded retry budget, not continuous polling. Turning Shared From off clears this cache without deleting favorites or other settings.

Favorites also save the HTTPS site origin, current tenant identifier, and Packages/Designer page type to separate tenants sharing one domain. Identity is read from already-loaded page state without an additional service call. Unknown identity or an incomplete storage read does not reuse another tenant's list. Verified tenant visits are remembered as scoped lists even without pins; this allows the extension to recognize multiple previously visited tenants on one domain. Older host/page-only lists carry over once to the actual loaded tenant when it is the only tenant known on that site. If multiple tenants are known, assignment requires your explicit choice in settings. The extension cannot know about an unvisited tenant; the first detected tenant is treated as the default, and later tenants do not inherit its old pins. Assigned duplicate recovery copies are removed only after reading back the saved tenant list and verifying every old pin is present. Unresolved, unmatched, malformed, or unverified copies remain saved; failed cleanup does not remove active favorites. Small assignment markers remain local to prevent automatic reapplication of removed pins.

You may explicitly export a JSON backup from settings. The file contains the extension version and export time; favorite site origins, tenant identifiers, page types, package/pipeline names, version identifiers, ordering and layout choices; any older favorite copies still awaiting safe assignment or verification; compact site/tenant/page assignment markers without duplicate package data; and any saved Shared From environment identifiers, labels, grouped names, and last-checked timestamps. Preserved source names without a known package are marked **Package Not Yet Recorded**. This is a local download, not an upload to the publisher or another service, and follows your browser's download preferences.

Import reads only a file you select and previews its tenant lists before you confirm. Merge preserves existing pin order; replacement requires separate confirmation and affects only matching lists in the file. Backups retain any old-list assignment association; when an older backup has one matching current tenant list, that current list takes precedence over its old recovery copy rather than reviving removed pins. Shared From restoration is optional and requires the existing local-data opt-in; it preserves observation times and does not replace newer snapshots with older ones. Import never grants website permissions or changes settings. Exported files are separate snapshots, do not update automatically, and are not deleted when you disable Shared From or remove the extension. You control where you keep or share those files; they may contain institution-specific names and tenant identifiers. Review them before sharing.

## Website permissions

**View Published Fitting Details** is an independent, off-by-default Designer setting. When enabled, it changes only the already-loaded published fitting's UI locks to allow scrolling, selection, and copying. Text/code remains read-only, action controls remain disabled, and drafts are unchanged. Only the boolean preference is stored; the feature does not retrieve, cache, export, or transmit fitting contents, read credentials, add permissions, or make service requests. Copying is initiated by you through the normal editor/browser clipboard controls. Disabling it restores native UI locks.

The two standard Experience sites remain enabled. For a custom site, the extension requests optional scripting access and permission for that exact HTTPS domain only after you choose to add or allow it. It also reads the extension's current site permissions to recover previously approved exact HTTPS custom domains into the removable list; this recovery grants no new access and ignores wildcard permissions, the two standard sites, and reserved Git server origins. Declaring optional HTTPS access lets users supply their own domains; it does not automatically grant access to every website or its subdomains. Only packaged extension scripts are registered, and the navigation controls remain limited to the supported Integration Packages/Designer routes. No browsing-history permission is requested.

## Sharing and tracking

The extension has no analytics, advertising, or publisher-operated data collection service. It does not sell information or send your browsing activity, search terms, or favorites to the publisher or advertising services.

Optional sharing lookups communicate with Ellucian using your existing session. Ellucian and your institution manage their own services and privacy practices; this policy covers the extension, not those services. Hosting providers and browser stores may process ordinary website visits or installation information under their own policies.

If you email support, the publisher receives the information you choose to include in that email. Please do not send passwords, tokens, student records, or other confidential information.

**Report Bug** opens a public GitHub issue form only when selected. The extension does not attach data or submit a report for you. Sharing-related failure warnings use fixed step/error codes in browser consoles; they do not include raw service exceptions, URLs, environment identifiers, package/pipeline names or contents, credentials, or student records. No persistent diagnostic log or automatic log upload is added. You control what you post, and should review all screenshots, console text, and exported files before sharing them; other page or browser logs are outside this extension's control.

## Your controls

You can disable search, hide favorites, and turn off Shared To or Shared From in the extension settings. Hiding favorites does not delete them; use their favorite icons to remove individual favorites. Turning Shared From off stops collection and clears its additional local cache. Removing a custom site revokes its optional domain access and stops future loading there; refresh any open page to clear previously injected controls. Site-specific favorites and widths are retained locally for reuse if you add the site again. Removing the extension removes its local extension storage through the browser. Closing or reloading the page clears its in-memory data, but not saved preferences or an enabled Shared From cache.
